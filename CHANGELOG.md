## 03.11.2026 · v0.7.1 Экспертиза Din3zh: реальный исследователь + ошибка СМИ (разграничение со скамом)
- **Инцидент с «возвращением к ROOT на iOS 27.0.1» от Динеша Шетти (@Din3zh)**: каналы WeChat ошибочно записали его в один ряд с kirby как «первооткрывателя уязвимостей». Анализ скриншотов выявил `uname=iPhone12,5` (iPhone 11 Pro / A13 / T8030) + логи привязанной загрузки через `img4` = **продолжение известной ветки bootrom usbliter8 вплоть до релизной сборки 27.0.1**. Это не новая уязвимость, не имеет отношения к цепочке Calif и неприменимо к чипам A14+ → V29 (*partially_true / high*).
- **Проверка квалификации автора**: аккаунт в X с 2011 года, официальная верификация, спикер BlackHat / DefCon / POC / OWASP, сертификаты OSCE / OSCP / OSWE — реальный опытный исследователь; демонстрация достоверна, но строго ограничена контрольной группой A12/A13.
- **Дополнение методологии архива**: «ошибка интерпретации в СМИ» (Din3zh) и «разрыв между заявлениями и опытом» (kirby) — принципиально разные вещи, их нельзя ставить в один ряд. В раздел README о скаме внесено соответствующее разграничение.
- Влияние на решения: генеральная линия неизменна; устройства на чипах A14/A15 к данной ветке отношения не имеют.

## 02.11.2026 · v0.6 Внесение третьей цепи AstraSaw (низкая достоверность) + подтверждение окна подписи и экосистемы
- **Анонс проекта AstraSaw (01.11)**: разработчик kirby swift (`@kirby_swiftios`) объявил о разработке инструмента для iOS 27.0–27.0.1 полупривязанного типа (подобно Dopamine). Заявил об обходе CASLR и стабильном krw, обход SPTM (через гонку в AGX UAT) не завершён. PoC публиковать отказался, заявлен релиз через 1–2 недели. Тестирование проводилось лишь на iPhone 15 Pro Max, поддержка iPad под вопросом → V21/V22 (*unverifiable, low confidence*).
- **Итоги расследования**: ① Профиль автора: новичок (GitHub `kirby-swift` с высокой вероятностью принадлежит ему же: веб-магазин для Telegram → утилиты на Swift → перенос патчфайндера ядра XPF с помощью нейросети; отсутствие CVE и опыта исследований безопасности) → V24; ② Упомянутые специалисты (`Lakr233`, `onejailbreak_`, `0xjohnny`, `Little_34306`) не ответили, в СМИ тишина; ③ «Обход SPTM через гонку AGX UAT» не имеет прецедентов (Titan шёл другим путём и закрыт в ≤17.4b3), среди 163 CVE обновления 27.2 нет записей по AGX/IOGPU/SPTM/TXM; ④ Поведенческий профиль сильно пересекается с историей скама, но прямых улик подделки нет — **инцидент внесён в архив для наблюдения, без включения в основной прогресс и без изменения ситуации для A14/A15**.
- **Исправление терминологии**: опечатка китайских перепечаток *«CASKR»* исправлена на CASLR (KASLR) по оригинальному скриншоту → V23.
- **Подтверждение окна подписи**: цифровая подпись iOS 27.0.1 по состоянию на 02.11 остаётся активной (подтверждено через API ipsw.me, включая iPad mini 6; подпись 27.0 закрыта) → V25.
- **Подтверждение экосистемы**: для ElleKit 1.2 заявлена поддержка rootless-инъекции для iOS 15–27 (arm64) — уровень инъекции твиков готов к моменту появления рабочего джейлбрейка → V26.
- Изменения README: добавлена дорожка kirby/AstraSaw (с пометкой сомнения ❓); в `CONTEXT.md` добавлен термин «Третья цепь (AstraSaw)»; в P4 внесено примечание о том, что AstraSaw не меняет судьбу A14.
- Влияние на решения: генеральные выводы без изменений (оставаться на 27.0.1 / не обновляться на 27.2 / ключевой сценарий — отчёт Calif + независимый SPTM); новая точка наблюдения — проверка наступления ETA (08–15 ноября).

## 31.10.2026 · v0.5 Релиз 27.2 + первая открытая деталь + новые факторы
- **Выход iOS 27.2 (27.10, сборка 24B119)**: устранено 163 CVE; Calif получил благодарность за 6 CVE — App Intents 112692, AVEVideoEncoder 112705 (повреждение памяти ядра), CoreAudio 113912, CoreGraphics 112611, шрифты CoreGraphics 113950 (Substrate+Esser), WebKit 112684; также в бюллетень iOS 27 внесены CVE-2026-28968 (ядро) и CVE-2026-86886 (TCC) → V16.
- **Уточнена веха раскрытия**: сообщество ожидает отчёт Calif **после закрытия подписи iOS 27.1** (ONE Jailbreak) → V20.
- **Независимое воспроизведение CVE-2026-112705 исследователем MMdAS**: на GitHub опубликован PoC и лог падения (`NumberOfTemporalLayers=16463` вызывает panic ядра AppleAVE2 на iPhone 17 Pro / 27.0.1); запись по фиксированному смещению без произвольного чтения/записи, **уровень DoS** — первая деталь цепочки попала в открытый доступ, но требует отдельной сложной вепонизации → V17.
- **Демонстрация root на 27.2 от ikotas00 (Ikotas Labs)**: скриншоты модификации иконок и оболочки root; исключительно односторонние картинки без CVE, обещаний релиза и подтверждений в прессе → V18 (*unverifiable, low confidence*, слухи о «второй цепи»).
- **Публикация Calif хэша SHA-256 (30.10)**: строка без сопроводительного текста квалифицирована как криптографическое хэш-обязательство (фиксация даты обнаружения уязвимости), версия и суть неизвестны → V19.
- Изменения README: схема v2 (дорожки MMdAS и Ikotas, сдвиг вехи раскрытия на закрытие 27.1); **создан глоссарий `CONTEXT.md`** (16 ключевых терминов предметной области).
- Влияние на решения: генеральный вывод прежний (оставаться на 27.0.1 / не переходить на 27.2); окно подписи 27.0.1 на исходе.

## 21.10.2026 · v0.3 Интервью Штефана Эссера: формат релиза и совместимость с поколениями
- **Интервью члена команды Calif Штефана Эссера (i0n1c) изданиям heise / Mac & i (вышло 19.10)**:
  1. Calif не будет выпускать утилиты для конечных пользователей, но опубликует отчёт для сторонних разработчиков и, возможно, выпустит PoC (после выхода исправлений от Apple);
  2. Цепочка **обходит защиту MIE**, Эссер подтвердил: *«в целом применима к любому iPhone под управлением 27.0.1 (предположительно включая iPad)»*;
  3. Большая часть уязвимостей уже закрыта в бета-версиях 27.2 → V9/V10/V11.
- **Корректировка P4**: позиция по A14 смягчена — вместо категоричного «обход PPL никогда не существовал, не хватает двух деталей» зафиксировано «компоненты обхода могут уже входить в цепочку Calif, ожидаем публикации отчёта». Это косвенное доказательство (заявление автора и компетенции команды), а не прямое техническое наследование (код MIE нельзя применить к PPL). Если в отчёте не будет наработок по PPL, вердикт вернётся к пессимистичному.
- Изменения README: обновлён баннер, примечание к аргументу 2, в таблице лагерей процессоров для PPL отмечено появление надежды.
- Влияние на решения: генеральный вывод неизменен (оставаться на 27.0.1); новая точка контроля — **наличие в отчёте Calif материалов по PPL/A14**.
