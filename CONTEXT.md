# Мониторинг инцидента с джейлбрейком iOS 27.0.1 · Глоссарий предметной области

[Русский](CONTEXT.md) | [中文版](CONTEXT_ZH.md)

Настоящий документ является авторитетным определением единого языка (ubiquitous language) данного репозитория. Термины во всех отчётах, утверждениях и обсуждениях должны строго соответствовать этим определениям. Здесь собраны только специфические для данного контекста понятия (общепринятые термины ИБ и программирования опущены).

## Язык предметной области (Language)

### Цепочки и компоненты

**Цепь (Chain)**:
Полная цепочка эксплойтов джейлбрейка, продемонстрированная Calif на iOS 27.0.1/27.1, включающая в себя побег из песочницы (sandbox escape), чтение/запись ядра (kernel r/w), обход уровней защиты памяти и механизмы персистентности. Точный состав звеньев публично не раскрыт.
_Избегать_: «уязвимость» (в единственном числе как общее понятие), «утилита / инструмент»

**Компонент / Деталь (Part / 零件)**:
Минимальный элемент цепочки, который может быть независимо раскрыт или воспроизведён (например, PoC для CVE-2026-112705 или готовящийся к публикации эксплойт KRW от lambda). Публикация компонента ≠ раскрытие всей цепочки.
_Избегать_: «уязвимость» (обобщённо), «утилита / инструмент»

**Воспроизведение (Reproduction / 复现)**:
Независимый вызов той же уязвимости сторонними исследователями на основе публичной информации с фиксацией доказательств (panic log / crash). Доказывает лишь то, что «уязвимость существует и может быть стриггерена», но не означает её пригодность для эксплуатации.
_Избегать_: «вепонизация», «джейлбрейк»

**Вепонизация (Weaponization / 武器化)**:
Процесс доработки PoC уровня падения/DoS до стабильного чтения/записи памяти или эскалации привилегий. Это самостоятельный сложный инженерный этап между воспроизведением бага и появлением рабочего инструмента.
_Избегать_: «воспроизведение», «эксплуатация» (в общем смысле)

**Хэш-обязательство (Hash commitment / 哈希承诺)**:
Публикация исследователем «голого» хэша SHA-256 для фиксации временной метки (timestamp) нераскрытой уязвимости (например, Райан Остин 05.08, lambda 14.10, Calif 30.10). Не раскрывает технического содержания, смысл становится понятен только ретроспективно.
_Избегать_: «раскрытие уязвимости», «PoC»

**Демонстрация кросс-версионной персистентности (Cross-version persistence demo / 跨版本持久化演示)**:
Способность, продемонстрированная Calif в видео от 04.11: включение режима Lockdown Mode → OTA-обновление до версии 27.2, где уязвимости исправлены → твики продолжают работать после перезагрузки. Доказывает, что механизм персистентности не опирается на постоянную эксплуатируемость исправленной уязвимости; механизм не раскрыт (догадки СМИ о CoreTrust остаются лишь предположениями), выпуск компонента не гарантирован. Отличается от классического untethered (выживание при перезагрузке): это «выживание при обновлении системы».
_Избегать_: «полноценный джейлбрейк» (обобщенно), «CT3» (не подтверждено)

### Чипы и уровни защиты

**Слой защиты (Protection Layer / 防护层)**:
Аппаратные механизмы защиты памяти в чипах Apple, сменяющие друг друга по поколениям: PPL (A12–A14 / M1) → SPTM (A15–A18 / M2–M4) → MIE (A19 / A20 / M5). Каждое поколение процессоров использует строго свой механизм (они не выстроены друг за другом в виде последовательных эшелонов обороны); код обхода защиты нового поколения не может напрямую использоваться для обхода старого механизма.
_Избегать_: «MIE заменил PPL» (эволюция через поколение, а не прямая замена), «пробитие MIE означает пробитие PPL»

**momentarius**:
Эксплойт обхода PPL на чипах A12/A13 от staturnzz и TheRealClarity (уже интегрирован в Dopamine 3.0 для iOS 16.6–18.7.1 и 26.0–26.0.1). 04.11 разработчик opa334 подтвердил: после публикации эксплойта чтения/записи ядра (KRW) от lambda устройства A12/A13 смогут оперативно получить поддержку в Dopamine благодаря momentarius — защитный слой для них решен заранее, не хватает лишь уязвимости ядра. Это резко контрастирует с ситуацией для A14+ (где сохраняется дефицит n-day обходов SPTM/PPL).
_Избегать_: «новая уязвимость» (это уже готовый компонент), «Titan» (отдельная ветка для A14–A17, ограниченная ≤17.4b3)

**Лагерь / Фракция (Camp / 阵营)**:
Группировка устройств по поколениям аппаратной защиты (лагеря PPL / SPTM / MIE + контрольная группа A12/A13), определяющая число недостающих компонентов до джейлбрейка и приоритет портирования в сообществе.
_Избегать_: «модель», «поколение устройств»

**Деталь пазла (Puzzle piece / 拼图)**:
Число недостающих критических компонентов, отделяющих конкретный лагерь от рабочего джейлбрейка (на данный момент для SPTM = 1: новая уязвимость ядра; для PPL = 2: обход PPL + новая уязвимость ядра; для A12/A13 = 0.5: лишь дождаться выхода KRW).
_Избегать_: «разрыв», «препятствие»

**Изолированный остров (Island / 孤岛)**:
Положение лагеря PPL / A14: для версий >17.4b3 нет публичного обхода PPL и нет независимого «Плана Б». Перспективы зависят исключительно от того, включит ли Calif наработки по PPL в свой write-up, а не от простого течения времени.
_Избегать_: «старейшие устройства», «безнадёжные» (категоричные суждения)

**Ромб решения (Decision Diamond / 判定菱形)**:
Обозначение положения «острова» на схемах прогресса — судьба A14 является вопросом выбора «да/нет» (*будет ли во write-up материал по PPL/A14*), поэтому отображается узлом проверки условий, а не шкалой прогресса.
_Избегать_: «шкала прогресса»

**Пустыня экосистемы (Ecosystem Desert / 生态荒漠)**:
Положение отдельных категорий гаджетов (например, Apple Watch): даже при наличии демонстрации джейлбрейка для них нет традиций разработки твиков, менеджеров пакетов и инфраструктуры расширений, из-за чего демонстрация с высокой вероятностью останется просто показом.
_Избегать_: «призрачные надежды» (обобщённо)

### Версии и окна подписи

**Окно (Window / 窗口)**:
Период времени, когда конкретная версия iOS одновременно удовлетворяет двум условиям: «всё ещё подписывается Apple» и «уязвимости цепочки ещё не исправлены». На данный момент верхняя граница для обычных iPhone/iPad — 27.0.1, для iPhone Duo — 27.1 (эксклюзивная сборка).
_Избегать_: «версия» (обобщённо), «поддержка»

**Закрытие окна подписи (Stop signing / 关签)**:
Прекращение серверами Apple выдачи цифровых подписей для IPSW конкретной версии. После этого прошиться на эту версию невозможно: на устройствах с чипами A12 и новее SHSH-блобы бесполезны, обновление необратимо, остаётся только временное ~90-дневное окно обновления через DelayOTA.
_Избегать_: «откат / даунгрейд» (в общепринятом смысле невозможен)

**Спот / Фьючерс (Spot vs Futures / 现货/期货)**:
Разделение между «наличным» джейлбрейком (для текущей версии уже существует рабочий публичный инструмент, например A16 на ≤17.3.1) и «фьючерсным» джейлбрейком (существует лишь потенциальная вероятность появления джейлбрейка в будущем, как на 27.0.1). Размен «спота» на «фьючерс» требует отдельного обоснования и по умолчанию не рекомендуется.
_Избегать_: «можно сделать джейлбрейк / нельзя сделать джейлбрейк» (размытое по времени утверждение)

### Механизмы мониторинга

**Модель релиза (Release Model / 发布模式)**:
Зафиксированная стратегия Calif: не разрабатывать утилит для конечных пользователей; после выхода исправлений от Apple выпустить технический отчёт (write-up) для сторонних разработчиков сообщества и, возможно, приложить PoC (интервью Эссера heise от 19.10). Заявленный срок выхода write-up от lambda от 04.11 — первое практическое действие этой стратегии с конкретными временными рамками.
_Избегать_: «выпуск утилиты для джейлбрейка», «показывает, но не делится» (оценочные суждения)

**Веха раскрытия (Disclosure Milestone / 披露里程碑)**:
Ожидаемый сообществом момент публикации отчёта (write-up) Calif. Первоначальный ориентир = после прекращения подписания iOS 27.1 (ONE Jailbreak); с 04.11.2026 конкретизирован анонсом lambda о выходе эксплойта KRW и write-up в течение недели (V30) — сейчас главный фокус направлен на релиз lambda, а закрытие подписи 27.1 служит фоновым ориентиром.
_Избегать_: «дата релиза» (нет официальных гарантий, заявленный срок может сдвигаться)

**Градация зрелости opa334 (opa334 Tier Vocabulary / opa334分级词汇)**:
Предложенная разработчиком opa334 в конце октября классификация джейлбрейков по степени завершенности:
- **Full** = уровень обхода PPL/SPTM (полноценный джейлбрейк);
- **Semi Full** = уровень уязвимости Cryptex;
- **Semi** = уровень обхода CoreTrust;
- **Semi Semi** = уровень чтения/записи ядра (KRW) + ненативное выполнение кода (категория текущих демонстраций Calif и Ikotas).
Используется для охлаждения ожиданий: на чипах A14+ эксплойт KRW дает лишь уровень Semi Semi, и для статуса Full обязательно требуется обход SPTM.
_Избегать_: «привязанный/непривязанный» (смешение понятий)

**План Б (Plan B / B计划)**:
Независимый от публикации Calif путь для лагеря A15: отдельный рабочий обход SPTM (валиден для ≤27.0.1, уже существует в готовом виде) + будущая новая уязвимость ядра. Для других лагерей плана Б не существует.
_Избегать_: «запасная цепочка», «вторая цепочка» (последнее относится к слухам об Ikotas)

**Вторая цепь (Second Chain / 第二链)**:
Предполагаемая независимая от цепочки Calif цепочка эксплойтов, на которую намекает демонстрация root на iOS 27.2 от Ikotas Labs (30.10); на данный момент подкреплена только скриншотами одной из сторон и не подтверждена.
_Избегать_: «План Б», «подтверждённый факт»

**Третья цепь (Third Chain / 第三链 / AstraSaw)**:
Заявленный 01.11 независимый проект джейлбрейка от kirby swift (`@kirby_swiftios`) для iOS 27.0–27.0.1 (полупривязанный формат, завершение цепочки заявлено через обход SPTM с использованием гонки в AGX UAT). Все технические заявления опираются исключительно на слова автора, отсутствуют PoC, подтверждения независимых экспертов и какие-либо прецеденты в литературе; у автора отсутствует опыт исследований безопасности. Присвоен статус высокого риска / сомнительно (с 03.11); инцидент внесён в архив для наблюдения, но не влияет на прогресс основной линии экосистемы.
_Избегать_: «Вторая цепь» (относится исключительно к слухам об Ikotas), «План Б» (независимая ветка SPTM для A15), «подтверждённый факт»

**Оценка цепочки по самозаявлениям (Self-Claim Rating / 自述链评级)**:
Стандартизированная процедура из 4 проверочных фильтров для любых вновь появляющихся заявлений о «независимых цепочках эксплойтов»:
① **Квалификационный фильтр** (соответствие подтверждённых проектов и опыта сделанным заявлениям);
② **Фильтр прецедентов** (наличие прецедентов в литературе и закрытых CVE подсистем);
③ **Фильтр авторитетного подтверждения** (наличие верификации экспертами, прессой или профильным сообществом);
④ **Фильтр поведенческого профиля** (возраст аккаунта, увод в приватные каналы, отказ от демонстрации PoC и сравнение с историческими признаками скама).
По результатам проверки заявлению присваивается категория *verified* / *unverifiable* / *высокий риск (high-risk doubtful)*, определяющая его статус в архиве. Первое применение: инцидент AstraSaw (не пройден ни один из четырёх фильтров, см. [research/astrasaw-audit.md](research/astrasaw-audit.md)). Сопоставительное применение: анонс lambda (V30): квалификационный фильтр (указана в бюллетене Apple CVE + член Calif) ✓, фильтр прецедентов (у команды 6 зарегистрированных CVE) ✓, фильтр подтверждения (публичный ответ opa334 + публикация ONE Jailbreak) ✓, поведенческий фильтр (публикация технического write-up вместо закрытого увода в платные каналы) ✓ — все 4 фильтра пройдены, заявленный срок отслеживается как высокодостоверный.
_Избегать_: суждений на основе интуиции, дискриминации по возрасту или гражданству
